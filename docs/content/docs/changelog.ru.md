Что изменилось в каждой версии keen-pbr и что делать при обновлении.

## 3.4.0 {#v3-4-0}

### Что нового

- **Списки доменов работают без настройки резолвера.** keen-pbr сам читает DNS-ответы, проходящие через роутер, и имена сайтов в TLS-, HTTP- и QUIC-соединениях и заполняет наборы ваших списков. Уже первое соединение с сайтом идёт по нужному маршруту. См. [DNS]({{< relref "/docs/configuration/dns#dns-перехват" >}}).
- **dnsmasq стал необязательным.** Он нужен только для отдельных DNS-серверов для некоторых списков или для своих DNS-серверов по умолчанию. См. [Нужен ли dnsmasq?]({{< relref "/docs/configuration/dns#do-i-need-dnsmasq" >}}). keen-pbr сам выбирает экземпляр dnsmasq, показывает его состояние в веб-интерфейсе и чинит, если dnsmasq потерял конфиг. Новые команды: `keen-pbr dnsmasq detect` и `keen-pbr dnsmasq remove`.
- **Балансировка нагрузки между несколькими каналами** (`strategy: "balance"` в outbound `urltest`) с весами. В сборке для Keenetic её нет. См. [Несколько провайдеров]({{< relref "/docs/configuration/multi-wan" >}}).
- **Автоопределение шлюза** для interface-outbounds и редактирование шлюза по умолчанию в веб-интерфейсе.
- **Новый веб-интерфейс**: компактный обзор, живая таблица текущих запросов, журнал запросов с пояснениями к меткам, панель диагностики (проверки ядра идут первыми), обновление данных по живому потоку вместо опроса, удобнее на телефоне, страница настроек показывает значения по умолчанию.
- **Проверки состояния** предупреждают об отсутствии NAT или строгом `rp_filter` на балансируемых каналах, о чужих fwmark, пересекающихся с `fwmark.mask`, и об отсутствующих расширениях iptables.
- **Endpoint для Prometheus** с задержкой проб и счётчиками балансировки и перехвата.
- **`keen-pbr test-routing`** принимает параметры пакета (протокол, порты, адреса, DSCP) и выполняется в демоне.
- **В конфиге по умолчанию** есть правило, которое не пускает локальные сети в туннели.
- Списки, которые не скачались при запуске, докачиваются в фоне.
- При удалении пакета убираются оставшиеся правила firewall и файлы dnsmasq.

### Обновление с 3.3.x {#upgrading-from-33x}

После обновления управление dnsmasq остаётся включённым, как в 3.3.x. Если dnsmasq вам не нужен, выключите **Управлять конфигурацией dnsmasq** в веб-интерфейсе (**Общее** > **Управление локальным DNS-сервером**) и выполните шаги отката: [Keenetic]({{< relref "/docs/getting-started/installation/keenetic#dnsmasq-rollback" >}}), [OpenWrt]({{< relref "/docs/getting-started/installation/openwrt#dnsmasq-rollback" >}}), [Debian]({{< relref "/docs/getting-started/installation/debian#dnsmasq-rollback" >}}). Без него не работают DNS-правила и основные DNS-серверы.

Что проверить после обновления:

- **Keenetic: модули ядра.** Домены теперь определяются перехватом. Если компонент **Модули ядра подсистемы Netfilter** ещё не установлен, установите его. Затем откройте страницу состояния в веб-интерфейсе и запустите проверку DNS.
- **Keenetic: dnsmasq.** Старый блок keen-pbr удалён из `/opt/etc/dnsmasq.conf`, исходный файл сохранён как `/opt/etc/dnsmasq.conf.keen-pbr.bak`. Если у dnsmasq не осталось DNS-серверов, пакет добавил блок `# BEGIN keen-pbr fallback upstream` с публичными серверами. Если выключите управление dnsmasq, замените их своими.
- **Изменились значения по умолчанию.**
  - `daemon.clear_dynamic_sets_on_apply` теперь `false`: адреса доменов сохраняются при применении конфига.
  - `ttl_ms` списка теперь нижняя граница; верхняя задаётся `intercept.max_ttl_ms`.
  - `iproute.process_router_traffic` равно `false`: правила маршрутизации действуют на устройства в сети, а не на трафик самого роутера.
- **Поля, которые больше не работают.** `dns.system_resolver`, `dns.dns_test_server` (используйте `intercept.dns.marker`) и `daemon.resolver_ready_timeout_seconds`; если они заданы, журнал предупредит. Старые поля `outbounds`, `candidates` и `weight` в `outbound_groups` заменены на `members`; старые конфиги продолжают работать.
- **Новое поле `version`.** В нём версия keen-pbr, для которой записан конфиг. keen-pbr ставит его, когда вы сохраняете конфиг в веб-интерфейсе. Если правите файл вручную, оставьте его.
