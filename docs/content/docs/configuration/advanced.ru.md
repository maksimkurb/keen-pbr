Большинству пользователей эта страница не понадобится.

Здесь описаны настройки для продвинутых сценариев и на уровне сервиса: `daemon`, `api`, `fwmark`, `iproute` и `lists_autoupdate`.

Часть настроек есть в веб-интерфейсе: **Общее** > **Настройки** > **Общие**, **Автообновление списков** и **Расширенные настройки маршрутизации**. Низкоуровневые поля видны после переключения **Режим настроек** на **Продвинутый**. Страница описывает все поля `config.json`; рядом с полем указано, где его найти в интерфейсе.

## daemon

Управляет путём к PID-файлу (файлу с номером процесса сервиса), каталогом кэша и общим поведением маршрутизации.

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `pid_file` | string | — | Путь к PID-файлу. Можно переопределить флагом `--pid-file` |
| `cache_dir` | string | `/var/cache/keen-pbr` | Каталог для кэшированных данных списков |
| `firewall_backend` | string | `"auto"` | Какой firewall использовать: `auto` (выбрать автоматически), `iptables` или `nftables` |
| `clear_dynamic_sets_on_apply` | boolean | `false` | Очищать динамические наборы (IP-адреса доменов, собранные из DNS-ответов и соединений) при каждом применении конфигурации или перезапуске сервиса. При обновлении списков и переключении каналов они не очищаются. Веб-интерфейс: **Очищать изученные адреса доменов при применении**. |
| `ipset_hashsize` | integer | отсутствует | Необязательный начальный размер хеш-таблицы {{< term "ipset" >}}, создаваемых бэкендом iptables (по умолчанию `1024`). Не действует с nftables. Допустимый диапазон: от 1 до 2147483648. Веб-интерфейс (**Продвинутый** режим): **Размер хеш-таблицы IPSet (ipset hashsize)**. При изменении наборы пересоздаются, а динамические наборы очищаются. |
| `ipset_maxelem` | integer | отсутствует | Необязательное максимальное число элементов ipset, создаваемых бэкендом iptables (по умолчанию `65536`). Не действует с nftables. Допустимый диапазон: от 1 до 4294967295. Веб-интерфейс: **Максимальное количество элементов в ipset (ipset maxelem)**. При изменении наборы пересоздаются, а динамические наборы очищаются. |
| `reuse_static_sets_on_runtime_refresh` | boolean | `true` | Не перезаполнять наборы списков при `SIGUSR1`, переключении `urltest`/`icmptest` и изменении состояния интерфейсов: обновляются только правила, это быстрее. При `false` наборы перезаполняются каждый раз. |
| `skip_marked_packets` | boolean | `true` | Не обрабатывать пакеты, которые уже помечены другой программой. Веб-интерфейс: **Не обрабатывать маркированные пакеты**. |
| `ipv6_enabled` | boolean | `true` | Маршрутизировать IPv6-трафик. При `false` IPv6 идёт как обычно, мимо keen-pbr. Веб-интерфейс: **Включить поддержку IPv6**. |
| `strict_enforcement` | boolean | `false` | Если интерфейс или шлюз outbound типа `interface` недоступен, не выпускать его трафик через обычное соединение: в таблицу outbound ставится маршрут из `strict_enforcement_action`. Можно задать для каждого outbound отдельно. Веб-интерфейс: **Блокировать трафик при недоступности outbound (kill-switch)**. |
| `strict_enforcement_action` | string | `"unreachable"` | Что делать с трафиком при `strict_enforcement`: `unreachable` сразу возвращает приложению сетевую ошибку, а `blackhole` молча отбрасывает пакеты до тайм-аута приложения. |
| `max_file_size_bytes` | integer | `8388608` (8 MiB) | Максимальный размер загруженного удалённого списка в байтах |
| `firewall_verify_max_bytes` | integer | `262144` | Сколько байт вывода `iptables`/`nft` читать при проверке правил firewall (`keen-pbr status`, страница состояния); `0` — без ограничения |
| `exec_timeout_seconds` | integer | `30` | Сколько секунд ждать вспомогательные скрипты keen-pbr (например, скрипт для dnsmasq), прежде чем остановить их. Минимум 1. |
| `exec_kill_grace_seconds` | integer | `2` | Сколько секунд дать скрипту на завершение после остановки, прежде чем убить его принудительно. Минимум 0. |

```json { filename="config.json" }
{
  "daemon": {
    "pid_file": "/var/run/keen-pbr.pid",
    "cache_dir": "/var/cache/keen-pbr",
    "firewall_backend": "auto",
    "clear_dynamic_sets_on_apply": false,
    "ipset_hashsize": null,
    "ipset_maxelem": null,
    "reuse_static_sets_on_runtime_refresh": true,
    "skip_marked_packets": true,
    "ipv6_enabled": true,
    "strict_enforcement": false,
    "strict_enforcement_action": "unreachable",
    "max_file_size_bytes": 8388608,
    "firewall_verify_max_bytes": 262144,
    "exec_timeout_seconds": 30,
    "exec_kill_grace_seconds": 2
  }
}
```

Каталог кэша хранит загруженные удалённые списки, чтобы они были доступны, если сеть недоступна при запуске.

## api

Управляет встроенным HTTP API-сервером, на котором работает веб-интерфейс.

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `enabled` | boolean | `false` | Включить HTTP API и веб-интерфейс. В конфиге, который ставит пакет `keen-pbr`, уже включено |
| `listen` | string | `"0.0.0.0:12121"` | Адрес и порт для прослушивания |
| `max_request_body_bytes` | integer | `1048576` | Максимальный размер тела запроса в байтах. Минимум 1024. |
| `read_timeout_seconds` | integer | `15` | Сколько секунд ждать запрос от клиента. Минимум 1. |
| `write_timeout_seconds` | integer | `15` | Сколько секунд отправлять ответ клиенту. Минимум 1. |
| `keep_alive_timeout_seconds` | integer | `20` | Сколько секунд держать соединение открытым между запросами. Минимум 1. |
| `authentication` | object | отключена | Вход по паролю: `enabled` и `password_hash`. При `enabled: true` хеш обязателен. Хеш создаёт `keen-pbr hash-password --update` или веб-интерфейс: **Безопасность**. |
| `cors.allowed_origins` | array | — | Адреса сайтов (origin), которым разрешено обращаться к API из браузера, например `"https://router.example"`. Только точные адреса `http://` или `https://`, без пути и масок. |

```json { filename="config.json" }
{
  "api": {
    "enabled": true,
    "listen": "0.0.0.0:12121",
    "max_request_body_bytes": 1048576,
    "read_timeout_seconds": 15,
    "write_timeout_seconds": 15,
    "keep_alive_timeout_seconds": 20,
    "authentication": { "enabled": false },
    "cors": { "allowed_origins": [] }
  }
}
```

Запустите `keen-pbr` с флагом `--no-api`, чтобы отключить API независимо от конфига. См. [REST API]({{< relref "/docs/rest-api" >}}) для описания эндпоинтов и управления сервисом во время работы.

## fwmark

Задаёт диапазон значений {{< term "fwmark" >}}. fwmark — метка, которую keen-pbr ставит на пакет, чтобы система отправила его в нужную таблицу маршрутизации (таблицу с маршрутами одного outbound). См. [fwmark и conntrack]({{< relref "/docs/concepts#fwmark-и-conntrack" >}}).

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `start` | string | `"0x00010000"` | Первое значение fwmark для назначения outbounds. Веб-интерфейс: **Начальное значение fwmark** |
| `mask` | string | `"0x00FF0000"` | Битовая маска fwmark. Веб-интерфейс: **Маска fwmark** |

```json { filename="config.json" }
{
  "fwmark": {
    "start": "0x00010000",
    "mask": "0x00FF0000"
  }
}
```

`mask` должна состоять из идущих подряд шестнадцатеричных цифр `F`, например `0x00FF0000`. Outbounds получают значения fwmark по порядку, начиная со `start`, в пределах `mask`.

{{< callout type="warning" >}}
Если другое программное обеспечение на вашей системе использует тот же диапазон fwmark, скорректируйте `start` и `mask`, чтобы избежать конфликтов.
{{< /callout >}}

## iproute

Задаёт номера таблиц маршрутизации и приоритеты правил `ip rule` (правил, по которым система выбирает таблицу по метке fwmark), которые keen-pbr создаёт для outbounds.

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `table_start` | integer | `150` | Первый ID таблицы маршрутизации для выделения под outbounds. Веб-интерфейс: **Начальное значение таблицы маршрутизации IP** |
| `rule_priority_start` | integer или null | `table_start` | Приоритет первой записи `ip rule`; `null` — такой же, как `table_start` |
| `process_router_traffic` | boolean | `false` | Применять правила маршрутизации к трафику самого роутера и собирать по нему IP-адреса доменов. При `false` keen-pbr обрабатывает только трафик устройств в сети. `detour` у DNS-серверов работает в любом случае. Веб-интерфейс (**Продвинутый** режим): **Обрабатывать собственный трафик роутера**. |

```json { filename="config.json" }
{
  "iproute": {
    "table_start": 150,
    "rule_priority_start": null,
    "process_router_traffic": false
  }
}
```

Outbounds получают последовательные ID таблиц, начиная с `table_start`. Проверьте, что эти ID не пересекаются с существующими таблицами маршрутизации. Нельзя начинать с зарезервированных ID: 0, 128, 250-260 и всех от 32000. Конфиг с таким `table_start` не пройдёт проверку, а при выделении номеров зарезервированные ID пропускаются.

При остановке keen-pbr убирает только свои маршруты. Маршруты, которые добавили вы или другие программы, остаются на месте.

## Резервный канал (failover)

Правила проверяются сверху вниз, и срабатывает первое подходящее. Поэтому два одинаковых правила с разными outbound не дают резервирования: до второго правила пакет никогда не дойдёт.

Если интерфейс первого outbound пропадёт, поведение зависит от `strict_enforcement`:

- выключен (по умолчанию) — трафик уйдёт через обычный шлюз провайдера, мимо VPN;
- включён — трафик будет заблокирован (как именно, задаёт `strict_enforcement_action`).

Чтобы трафик переключался на запасной канал, создайте один outbound типа `urltest` (или `icmptest`) и добавьте в него оба интерфейса. Параметр `conntrack_on_switch` определяет, что происходит с уже открытыми соединениями, когда он переходит на более быстрый канал: `preserve` (по умолчанию) оставляет их на старом канале, `delete` удаляет их записи из {{< term "conntrack" >}}, и приложения переподключаются через новый. Если выбранный канал перестал работать, записи conntrack его соединений удаляются всегда.

## Что важно знать

- При `ipv6_enabled: false` IPv6-трафик идёт как обычно, мимо keen-pbr.
- keen-pbr узнаёт IP-адреса доменов из обычных DNS-ответов, которые проходят через роутер, даже если клиент пользуется сторонним DNS-сервером. Если устройство использует зашифрованный DNS ({{< term "DoH" >}}, {{< term "DoT" >}}), keen-pbr узнает адрес сайта только из самого соединения (имя сервера в TLS, HTTP или {{< term "QUIC" >}}), и первые соединения могут пройти мимо VPN. Чтобы этого избежать, отключите на устройстве «безопасный DNS» и настройте DoH/DoT на самом роутере.
- Когда у адреса домена истекает срок в списке, новые соединения идут уже по другому маршруту, а открытые продолжают идти прежним: их {{< term "fwmark" >}} хранится в {{< term "conntrack" >}}.
- `keen-pbr download` скачивает списки в кэш. Чтобы работающий сервис начал их использовать, выполните `keen-pbr download --reload` или перезапустите сервис.
- Если keen-pbr остановился после сбоя, не меняйте `fwmark.mask` до следующего запуска: иначе он не узнает свои старые правила и не сможет их удалить. Если так уже случилось, перезагрузите роутер.

## Только один экземпляр

На одном роутере может работать только один keen-pbr. Отдельный `pid_file` не помогает: второй экземпляр использует те же имена правил и наборов firewall и сломает правила первого.

Все outbound и правила маршрутизации описывайте в одной конфигурации. Если нужны два независимых экземпляра, запускайте их в разных сетевых пространствах имён ({{< term "network namespace" >}}).

## lists_autoupdate

Обновление удалённых списков по расписанию.

Если секции `lists_autoupdate` нет, автоматическое обновление выключено. В веб-интерфейсе: **Общее** > **Настройки** > **Автообновление списков**.

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `enabled` | boolean | `false` | Включить автоматическое обновление списков. Веб-интерфейс: **Включить автообновление списков** |
| `cron` | string | — | Расписание обновления: выражение cron из 5 полей (формат ниже). Веб-интерфейс: **Расписание обновления** |

```json { filename="config.json" }
{
  "lists_autoupdate": {
    "enabled": true,
    "cron": "0 4 * * 0"
  }
}
```

Формат `cron`: `минута час день-месяца месяц день-недели`. Пример выше запускается раз в неделю в воскресенье в 04:00.

Если `cron` заполнено, оно проверяется, даже когда `enabled` равно `false`. При `enabled: true` оно обязательно.

Если удалённый список не удалось скачать при старте, демон повторяет попытки в фоне с увеличивающимися паузами (10 секунд, 30 секунд, 2 минуты, затем каждые 5 минут), пока загрузка не удастся. Это не зависит от `lists_autoupdate`.

Обновить списки вручную можно в любой момент:

```bash
keen-pbr download --reload
```
