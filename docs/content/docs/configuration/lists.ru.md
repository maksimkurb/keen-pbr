Списки — это группы сайтов или диапазонов IP, которые вы хотите, чтобы keen-pbr сопоставлял.

Ключ `lists` — это объект, где каждый ключ — это имя списка, а значение — конфигурация списка.

Имена списков должны соответствовать `^[a-z][a-z0-9_]*$` и быть не более 24 символов.

Большинство пользователей начинают с простого списка доменов:

```json { filename="config.json" }
{
  "lists": {
    "my_sites": {
      "domains": ["google.com", "youtube.com"]
    }
  }
}
```

## Поля

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `url` | string | нет | URL удалённого файла списка для загрузки и кэширования |
| `domains` | array of string | нет | Встроенные DNS-совместимые доменные паттерны (поддерживает начальный `*.`) |
| `ip_cidrs` | array of string | нет | Встроенные IP-адреса или диапазоны CIDR |
| `file` | string | нет | Путь к локальному файлу списка |
| `ttl_ms` | integer | нет (по умолчанию: `0`) | Минимальный тайм-аут для IP-адресов, полученных DNS/L7-перехватом. Если поле опущено, равно `0` или меньше 1000 мс, используется `intercept.min_ttl_ms`; большие значения округляются вниз до секунд. TTL DNS-записи может увеличить срок до `intercept.max_ttl_ms`. |

Встроенные списки, локальные файлы и списки по URL используют одинаковый синтаксис
доменов. Начальный `*.` и одна завершающая корневая точка удаляются, поэтому
`*.google.com` нормализуется до `google.com`. В служебных DNS-метках разрешены
символы подчёркивания; пробелы, разделители директив, некорректные маски и метки в
файлах пропускаются, а во встроенной конфигурации отклоняются.

URL удалённых списков и все перенаправления должны использовать HTTP или HTTPS.
Приватные и локальные HTTP(S)-адреса остаются разрешёнными для списков внутри роутера.

Локальные источники должны быть обычными файлами, а не символическими ссылками,
устройствами или FIFO. Для локальных и кэшированных файлов действует ограничение
`daemon.max_file_size_bytes` (по умолчанию 8 МиБ), а длина строки ограничена 4096 байтами.

Должен быть предоставлен хотя бы один из `url`, `domains`, `ip_cidrs` или `file`.

{{< callout type="warning" >}}
Если вы объединяете несколько источников в одной записи списка, все записи объединяются, но это не рекомендуется и может быть запрещено в будущих версиях.
{{< /callout >}}

{{% details title="Под капотом: как сопоставляются списки доменов" closed="true" %}}
Каждый список поддерживается статическими и динамическими наборами IP.

- Статические записи из `ip_cidrs`, `file` и `url` загружаются немедленно.
- Записи доменов добавляются позже, когда DNS/L7-перехват их наблюдает.
- Полученные IP-адреса истекают по TTL DNS-записи с ограничениями `intercept.min_ttl_ms` и `intercept.max_ttl_ms`; `ttl_ms` задаёт нижнюю границу для списка. Это значение не связано с интервалом обновления удалённых списков.
{{% /details %}}

## Формат файла списка

Независимо от того, загружается ли из `url` или `file`, keen-pbr ожидает одну запись на строку:

- IPv4-адрес: `93.184.216.34`
- IPv4 CIDR: `10.0.0.0/8`
- IPv6-адрес: `2606:2800:220:1:248:1893:25c8:1946`
- IPv6 CIDR: `2001:db8::/32`
- Домен: `example.com` — сопоставляет домен и все его поддомены
  - Домен с wildcard: `*.example.org` эквивалентен `example.org`, поэтому **нет необходимости** добавлять `*.` перед доменом. Для совместимости префикс `*.` автоматически удаляется
- Комментарии: строки, начинающиеся с `#`, игнорируются
- Пустые строки игнорируются

## Примеры

### Удалённый список по URL

```json { filename="config.json" }
{
  "lists": {
    "remote_list": {
      "url": "https://raw.githubusercontent.com/v2fly/domain-list-community/refs/heads/master/data/apple"
    }
  }
}
```

Загруженные файлы кэшируются в `daemon.cache_dir`. Если URL недоступен при запуске, используется кэшированная копия.

{{< callout type="warning" >}}
Чтобы избежать повторной загрузки одного и того же списка снова и снова, даже если он не изменился, удалённый сервер должен поддерживать `If-Modified-Since` или `ETag`.
{{< /callout >}}

### Встроенный список доменов

```json { filename="config.json" }
{
  "lists": {
    "my_domains": {
      "domains": ["example.com", "other.org"]
    }
  }
}
```

Обе записи сопоставляют домен и все его поддомены. Написание `*.example.com` эквивалентно `example.com` — префикс `*.` автоматически удаляется keen-pbr.

### Встроенный список IP

```json { filename="config.json" }
{
  "lists": {
    "my_ips": {
      "ip_cidrs": [
        "93.184.216.34",
        "10.0.0.0/8",
        "2606:2800:220:1:248:1893:25c8:1946",
        "2001:db8::/32"
      ]
    }
  }
}
```

### Локальный файл

```json { filename="config.json" }
{
  "lists": {
    "local_list": {
      "file": "/etc/keen-pbr/my-list.txt"
    }
  }
}
```

Все четыре источника объединяются в один список. `ttl_ms: 86400000` задаёт нижнюю границу в 24 часа для IP-адресов, полученных DNS/L7-перехватом и записанных в динамические наборы (`kpbr4d_combined` / `kpbr6d_combined`). Статические IP из `ip_cidrs` и кэшированного URL/файла загружаются в стабильные наборы (`kpbr4_combined` / `kpbr6_combined`) и не истекают автоматически. При обновлении статического набора через iptables используется временный набор, который затем меняется с активным.
