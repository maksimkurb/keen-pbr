Списки — это группы сайтов или диапазонов IP, трафик к которым keen-pbr будет направлять по вашим правилам.

Ключ `lists` — это объект, где каждый ключ — это имя списка, а значение — конфигурация списка.

Имя списка: строчные латинские буквы, цифры и `_`, начинается с буквы, не длиннее 24 символов (`^[a-z][a-z0-9_]*$`).

Большинство пользователей начинают с простого списка доменов:

```json { filename="config.json" }
{
  "lists": {
    "my_sites": {
      "domains": ["google.com", "youtube.com"]
    }
  }
}
```

## Поля

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `url` | string | нет | URL удалённого файла списка для загрузки и кэширования |
| `domains` | array of string | нет | Домены прямо в конфиге. `*.` в начале писать не обязательно |
| `ip_cidrs` | array of string | нет | IP-адреса и подсети ({{< term "CIDR" >}}) прямо в конфиге |
| `file` | string | нет | Путь к локальному файлу списка |
| `ttl_ms` | integer | нет (по умолчанию: `0`) | Сколько минимум хранить IP-адреса доменов этого списка, в миллисекундах. Если не задано или меньше 1000, используется `intercept.min_ttl_ms`. Если {{< term "TTL" >}} в DNS-ответе больше, адрес хранится дольше, но не больше `intercept.max_ttl_ms` |

Домены записываются одинаково во всех источниках. `*.google.com` и `google.com` означают одно и то же. Некорректные домены в файлах и списках по URL пропускаются, а в `domains` — приводят к ошибке конфигурации.

Списки по URL скачиваются только по HTTP или HTTPS, в том числе с адресов в локальной сети.

Локальный файл должен быть обычным файлом (не символической ссылкой). Размер файла ограничен `daemon.max_file_size_bytes` (по умолчанию 8 МиБ), длина строки — 4096 байтами.

Должен быть предоставлен хотя бы один из `url`, `domains`, `ip_cidrs` или `file`.

{{< callout type="warning" >}}
Если вы объединяете несколько источников в одной записи списка, все записи объединяются, но это не рекомендуется и может быть запрещено в будущих версиях.
{{< /callout >}}

{{% details title="Под капотом: откуда берутся IP-адреса доменов" closed="true" %}}
- IP-адреса и подсети из `ip_cidrs`, `file` и `url` загружаются сразу при запуске.
- IP-адреса доменов keen-pbr узнаёт позже, когда устройство в сети обращается к сайту (из DNS-ответа или из самого соединения).
- IP-адрес домена хранится столько, сколько указано в DNS-ответе, но не меньше `ttl_ms` списка и в пределах `intercept.min_ttl_ms`–`intercept.max_ttl_ms`. Это не связано с тем, как часто обновляются списки по URL.
{{% /details %}}

## Формат файла списка

Независимо от того, загружается ли из `url` или `file`, keen-pbr ожидает одну запись на строку:

- IPv4-адрес: `93.184.216.34`
- IPv4 {{< term "CIDR" >}}: `10.0.0.0/8`
- IPv6-адрес: `2606:2800:220:1:248:1893:25c8:1946`
- IPv6 CIDR: `2001:db8::/32`
- Домен: `example.com` — подходит сам домен и все его поддомены
  - Домен с wildcard: `*.example.org` эквивалентен `example.org`, поэтому **нет необходимости** добавлять `*.` перед доменом. Для совместимости префикс `*.` автоматически удаляется
- Комментарии: строки, начинающиеся с `#`, игнорируются
- Пустые строки игнорируются

## Примеры

### Удалённый список по URL

```json { filename="config.json" }
{
  "lists": {
    "remote_list": {
      "url": "https://raw.githubusercontent.com/v2fly/domain-list-community/refs/heads/master/data/apple"
    }
  }
}
```

Загруженные файлы кэшируются в `daemon.cache_dir`. Если URL недоступен при запуске, используется кэшированная копия.

{{< callout type="warning" >}}
Чтобы избежать повторной загрузки одного и того же списка снова и снова, даже если он не изменился, удалённый сервер должен поддерживать `If-Modified-Since` или `ETag`.
{{< /callout >}}

### Встроенный список доменов

```json { filename="config.json" }
{
  "lists": {
    "my_domains": {
      "domains": ["example.com", "other.org"]
    }
  }
}
```

Обе записи подходят для домена и всех его поддоменов. Написание `*.example.com` эквивалентно `example.com` — префикс `*.` автоматически удаляется keen-pbr.

### Встроенный список IP

```json { filename="config.json" }
{
  "lists": {
    "my_ips": {
      "ip_cidrs": [
        "93.184.216.34",
        "10.0.0.0/8",
        "2606:2800:220:1:248:1893:25c8:1946",
        "2001:db8::/32"
      ]
    }
  }
}
```

### Локальный файл

```json { filename="config.json" }
{
  "lists": {
    "local_list": {
      "file": "/etc/keen-pbr/my-list.txt"
    }
  }
}
```

Все четыре источника объединяются в один список. `ttl_ms: 86400000` означает, что IP-адреса доменов из этого списка хранятся не меньше 24 часов. IP-адреса из `ip_cidrs`, файла и URL хранятся, пока не изменится сам список.
