## Какой бэкенд firewall будет использоваться?

При `daemon.firewall_backend: "auto"` (по умолчанию) keen-pbr использует nftables, если установлена команда `nft`, а иначе iptables/ipset.

## Как перезагрузить списки без перезапуска сервиса?

Используйте `SIGHUP`:

```bash {filename="bash"}
kill -HUP $(cat /var/run/keen-pbr.pid)
```

Это запускает полную перезагрузку: заново скачиваются все удалённые списки и повторно применяются правила firewall и маршрутизации.

{{% details title="Чем отличается SIGUSR1" %}}
`SIGUSR1` работает иначе: он заново проверяет таблицы маршрутизации и запускает URL-тесты немедленно, но списки заново не скачивает.
{{% /details %}}

## Что произойдёт, если URL удалённого списка недоступен при запуске?

keen-pbr использует кэшированную копию из `daemon.cache_dir`, если она доступна. Если кэша тоже нет, список только с `url` остаётся пустым, пока загрузка не удастся; keen-pbr продолжает попытки в фоне.

## Как urltest outbound выбирает лучший канал?

Каждые `interval_ms` keen-pbr отправляет HTTP-запрос на настроенный `url` через каждый канал и измеряет задержку ({{< term "RTT" >}}). При `strategy: "priority"` выбирается канал с наименьшей задержкой. Если новый лучший канал быстрее текущего меньше чем на `tolerance_ms`, переключения не происходит. Каналы проверяются по группам: следующая группа из `outbound_groups` используется, только если в предыдущей не работает ни один канал.

Если канал `failure_threshold` раз подряд не прошёл проверку, keen-pbr перестаёт его использовать на `timeout_ms`, а затем снова проверяет его несколько раз. Так трафик не прыгает между каналами, пока один из них работает нестабильно.

## Можно ли маршрутизировать DNS-запросы через VPN?

Да. Используйте поле `detour` в `dns.servers`, чтобы привязать DNS-запросы к этому серверу к конкретному outbound:

```json
{
  "servers": [
    {
      "tag": "vpn_dns",
      "address": "10.8.0.1",
      "detour": "vpn"
    }
  ]
}
```

## Какой формат файла списка?

Одна запись на строку. Поддерживаемые форматы:
- IPv4-адрес: `93.184.216.34`
- IPv6-адрес: `2606:2800:220:1:248:1893:25c8:1946`
- {{< term "CIDR" >}}: `10.0.0.0/8`
- Домен: `example.com` (автоматически включает все поддомены)
  - записи вида `*.example.com` также поддерживаются и обрабатываются так же, как `example.com`
- Строки, начинающиеся с `#`, являются комментариями и игнорируются
- Пустые строки игнорируются

## Как проверить, что маршрутизация правильно применена?

Выполните:

```bash {filename="bash"}
keen-pbr status
```

keen-pbr сравнит правила firewall, таблицы маршрутизации и записи `ip rule` в ядре с тем, что он ожидает, и отметит каждый пункт как `OK`, `MISSING` или `MISMATCH`. Та же проверка есть на странице состояния в веб-интерфейсе и в `GET /api/health/routing`. Чтобы проверить конкретный сайт, используйте `keen-pbr test-routing <домен-или-ip>`.

## Можно ли объединить несколько источников в одном списке?

Да. Можно объединять `url`, `domains`, `ip_cidrs` и `file` в одной записи списка — все данные сольются воедино:

```json
{
  "lists": {
    "combined": {
      "url": "https://example.com/remote.txt",
      "domains": ["extra.example.com"],
      "ip_cidrs": ["192.168.100.0/24"],
      "file": "./local.txt"
    }
  }
}
```

{{< callout type="warning" >}}
Веб-интерфейс умеет объединять только `ip_cidrs` и `domains`. Объединять их с `url` или `file` веб-интерфейс не умеет, и делать так не рекомендуется: в будущих версиях это может быть запрещено.
{{< /callout >}}
