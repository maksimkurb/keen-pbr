keen-pbr можно установить на роутерах Keenetic / NetCraze через менеджер пакетов {{< term "Entware" >}} `opkg`.

{{% steps %}}

### Установите Entware на роутере

Сначала убедитесь, что {{< term "Entware" >}} установлена на вашем роутере. Пожалуйста, обратитесь к официальному руководству для [Keenetic](https://support.keenetic.com/?lang=ru) или [NetCraze](https://support.netcraze.ru/?lang=ru):

1. Найдите руководство для вашей модели роутера.
2. В строке поиска найдите "Установка репозитория Entware на USB-накопитель".
3. Внимательно прочитайте инструкции и выполните их.

### Установите необходимые компоненты

Откройте страницу конфигурации роутера, перейдите в **Управление** -> **Настройки системы** и установите следующие дополнительные компоненты:

- Сетевые функции / **Протокол IPv6** (на NDMS 5.0+ отсутствует, т.к. встроен в систему)
- Пакеты OPKG / **Поддержка открытых пакетов**
- Пакеты OPKG / **Модули ядра подсистемы Netfilter**
- Пакеты OPKG / **Пакет расширений Xtables-addons для Netfilter**
- Утилиты и сервисы / **Прокси-сервер DNS-over-TLS** (необязательно, но настоятельно рекомендуется)
- Утилиты и сервисы / **Прокси-сервер DNS-over-HTTPS** (необязательно, но настоятельно рекомендуется)

### Настройте DoH/DoT на роутере

Рекомендуется настроить DNS-серверы {{< term "DoH" >}}/DoT на роутере, чтобы защититься от атак с подменой DNS.

См. официальную документацию Netcraze: [Прокси DoH и DoT для шифрования DNS-запросов](https://support.netcraze.ru/ultra/nc-1812/ru/31543.html).

### Установите `keen-pbr` из репозитория

1. Откройте [страницу репозитория keen-pbr](https://repo.keen-pbr.fyi/repository/stable/?lang=ru).
2. Выберите "**Keenetic / NetCraze**" в селекторе ОС слева, затем выберите версию "**current**" и архитектуру, соответствующую вашему роутеру.
    - Подсказка: в SSH-сессии можно выполнить `opkg print-architecture`, чтобы узнать архитектуру роутера.
3. Внимательно следуйте инструкциям на странице репозитория шаг за шагом.
4. Выполните команду `opkg install keen-pbr`.
    - Пример команды установки:
      ```bash {filename="bash"}
      opkg install keen-pbr

      # или если нужна версия без API и без Web UI
      # opkg install keen-pbr-headless
      ```

### Убедитесь, что сервис `keen-pbr` запущен

Перед тем как переходить к следующему шагу, рекомендуется проверить, что `keen-pbr` успешно запустился и не завершился с ошибкой. Выполните `/opt/etc/init.d/S80keen-pbr status`. Если сервис не запущен, см. раздел [Устранение неполадок]({{< relref "/docs/troubleshooting#service-does-not-start" >}}).

Пример:
```
~ # /opt/etc/init.d/S80keen-pbr status
 Checking keen-pbr...              alive.
```

Если сервис находится в состоянии **alive**, переходите к следующему шагу.

### Включите `dns-override`

После установки `keen-pbr` нужно включить `dns-override`, чтобы все DNS-запросы от клиентов LAN перенаправлялись в {{< term "Entware" >}}:

1. Откройте http://my.keenetic.net/a (если ссылка не открывается, вместо нее откройте `http://<ip-роутера>/a`)
2. Выполните команды `opkg dns-override`, а затем `system configuration save`
3. Перезагрузите роутер. **Это очень важно: без перезагрузки опция не станет активной.**

### Настройте сервис

После перезагрузки роутера можно открыть http://my.keenetic.net:12121 и настроить keen-pbr через веб-интерфейс (если установлена полная версия; у headless-версии Web UI отсутствует).

Также keen-pbr можно настроить вручную, изменив файл конфигурации: `/opt/etc/keen-pbr/config.json`.

### Выберите RAW или mangle PREROUTING

Этот выбор есть только на Keenetic / NetCraze. keen-pbr ставит {{< term "fwmark" >}} в одной из двух таблиц firewall:

- **{{< term "mangle" >}}**: Keenetic время от времени пересобирает эту таблицу (например, при продлении аренды адреса по DHCP), и правила keen-pbr ненадолго пропадают, пока keen-pbr их не восстановит;
- **raw**: её Keenetic не трогает, но правила из раздела **Приоритеты подключений** > **Применение политик** срабатывают позже и перезаписывают fwmark keen-pbr.

Подробнее о том, как Keenetic пересобирает iptables, — в [обсуждении на форуме Keenetic Community](https://forum.keenetic.ru/topic/20631-keenetic-ndms-%D0%BE%D1%87%D0%B8%D1%89%D0%B0%D0%B5%D1%82-iptables-%D0%B2%D0%BE-%D0%B2%D1%80%D0%B5%D0%BC%D1%8F-%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA%D0%B0-%D0%BF%D1%80%D0%BE%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%D1%8B/).

| Режим | Преимущество | Компромисс |
|---|---|---|
| **RAW** (по умолчанию, если доступна) | PBR остаётся активным при пересборке mangle Keenetic. Долгие чувствительные соединения, например игровые сессии, не будут разрываться из-за пересборки; меньше шансов, что пакеты уйдут мимо VPN. | После установки `fwmark` в RAW правила Keenetic в разделе **Приоритеты подключений** > **Применение политик** перезаписывают его. Поэтому RAW работает только для устройств, которым назначена **Политика по умолчанию**. |
| **mangle** | keen-pbr выполняется после того, как Keenetic поставит свои {{< term "fwmark" >}} по правилам из раздела **Приоритеты подключений** > **Применение политик**, и может переопределять маршрутизацию устройств с нестандартной политикой. | Когда Keenetic пересобирает таблицу `mangle` (обычно примерно раз в пять минут), правила keen-pbr ненадолго исчезают. Несколько пакетов могут уйти по обычному маршруту до их восстановления, разорвав игровую сессию или другое чувствительное соединение. |

{{< callout type="info" >}}
Для наиболее предсказуемой работы keen-pbr на Keenetic не назначайте устройствам политики в разделе **Приоритеты подключений**. Вместо этого создайте эквивалентные [правила маршрутизации keen-pbr]({{< relref "/docs/configuration/route-rules" >}}), указав для устройства `src_addr` (**Исходный адрес**). Так правила маршрутизации останутся в keen-pbr и не будут конфликтовать с политиками Keenetic.
{{< /callout >}}

По умолчанию keen-pbr отдельно для IPv4 и IPv6 проверяет, доступна ли RAW, и использует её, если доступна, иначе mangle. Какой режим выбран, видно в системном журнале после запуска сервиса:

```text
IPv4 raw PREROUTING available
WARNING: IPv6 raw PREROUTING unavailable: ...
```

Чтобы всегда использовать mangle, добавьте в `/opt/etc/keen-pbr/defaults` строку:

```sh
KEEN_PBR_RAW_PREROUTING="disable"
```

и перезапустите сервис:

```sh
/opt/etc/init.d/S80keen-pbr restart
```

Остальные значения этой переменной описаны в разделе [CLI]({{< relref "/docs/cli#--use-raw-prerouting" >}}).

Основные команды:

| Действие | Команда |
| --- | --- |
| Запустить сервис | `/opt/etc/init.d/S80keen-pbr start` |
| Перезапустить сервис | `/opt/etc/init.d/S80keen-pbr restart` |
| Проверить, что **keen-pbr** работает | `/opt/etc/init.d/S80keen-pbr status` |

{{< callout type="info" >}}
Если вы не планируете использовать Web UI или API keen-pbr, рассмотрите установку пакета `keen-pbr-headless`.
Он занимает меньше места (~1.2 МБ вместо ~2.8 МБ) и вообще не включает API-сервер. Также API-сервер можно отключить в любой момент через флаг конфигурации, даже если используется полная версия пакета.
{{< /callout >}}

### Следующие шаги

Перейдите на страницу [Быстрый старт]({{< relref "/docs/getting-started/quick-start" >}}) и используйте вкладку **Web UI** для самой простой первоначальной настройки. Если вы установили версию `headless`, вместо этого откройте вкладку **JSON / CLI**.

## Обновление с интеграции dnsmasq

Старые версии keen-pbr всегда добавляли свой блок в `/opt/etc/dnsmasq.conf`. Текущей версии он не нужен, и при обновлении пакет сам наводит порядок:

- удаляет блок keen-pbr из `/opt/etc/dnsmasq.conf`, а исходный файл сохраняет как `/opt/etc/dnsmasq.conf.keen-pbr.bak`;
- если у dnsmasq не останется ни одного DNS-сервера, к которому он отправляет запросы, добавляет блок `# BEGIN keen-pbr fallback upstream` с публичными DNS-серверами. **Проверьте его** и при необходимости замените своими серверами;
- один раз перезапускает dnsmasq.

Можно и вовсе удалить dnsmasq из {{< term "Entware" >}} и пользоваться встроенным DNS-прокси Keenetic: keen-pbr работает с любым резолвером.

Для [отдельных DNS-серверов для списков]({{< relref "/docs/configuration/dns#per-list-dns-servers-dnsmasq" >}}) нужен `dnsmasq-full` из Entware в роли DNS-сервера для локальной сети. Когда вы их включаете, keen-pbr добавляет в `/opt/etc/dnsmasq.conf` блок `# BEGIN keen-pbr upstream dns`.
