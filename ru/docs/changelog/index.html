      Список изменений

      Список изменений

      • Open in ChatGPT

      Что изменилось в каждой версии keen-pbr и что делать при обновлении.

      3.4.0

      Что нового

      • Списки доменов работают без настройки резолвера.
        keen-pbr сам читает DNS-ответы, проходящие через роутер, и имена сайтов в TLS-, HTTP- и QUIC-соединениях и заполняет наборы ваших списков. Если устройство получает адрес сайта через обычный DNS, уже первое соединение с сайтом идёт по нужному маршруту. Если устройство использует зашифрованный DNS, keen-pbr узнаёт сайт только по имени в начале соединения. Это первое соединение обрывается, и браузер или приложение подключается заново, уже по нужному маршруту. Если в ядре чего-то не хватает, отключается только эта часть (DNS или соединения), а причина видна на странице состояния. См. DNS.
      • dnsmasq стал необязательным.
        Он нужен, только если вы хотите настроить split DNS, то есть использовать разные DNS-серверы в зависимости от домена, или задать DNS-серверы для всей сети прямо в keen-pbr. См. Нужен ли dnsmasq?. keen-pbr сам выбирает экземпляр dnsmasq, показывает его состояние в веб-интерфейсе и чинит, если dnsmasq потерял конфиг. Новая команда: keen-pbr resolver dnsmasq detect.
      • DNS-серверы Keenetic можно привязать к группе DNS-прокси. Keenetic/NetCraze
        Добавлен выбор группы DNS-прокси (например, Policy0) для DNS-сервера типа keenetic: домены списка разрешаются через серверы этой группы. Серверов с типом keenetic теперь может быть несколько. Если группу удалили на роутере, запросы блокируются или идут через System, на странице состояния появляется проблема. Кнопка Обновить сейчас перечитывает группы с роутера. См. DNS.
      • Балансировка нагрузки между несколькими каналами. OpenWrtDebian
        Outbound urltest или icmptest с strategy: "balance" распределяет соединения между каналами, у каждого канала свой вес. Соединение остаётся на канале, через который началось. См. Балансировка нагрузки между несколькими WAN.
      • Автоопределение шлюза.
        У outbound interface можно указать "gateway": "auto", а шлюз по умолчанию теперь редактируется в веб-интерфейсе. См. interface.
      • Весь интернет-трафик через резервный канал или балансировку. nftables
        Новое условие правила default_gateway. См. Правила маршрутизации.
      • Новый веб-интерфейс.
        Компактный обзор, живая таблица текущих запросов, журнал запросов с пояснениями к меткам и фильтрами, панель диагностики (проверки ядра идут первыми), новый редактор outbounds, обновление данных по живому потоку вместо опроса, удобнее на телефоне, страница настроек показывает значения по умолчанию.
      • Проверки состояния.
        keen-pbr предупреждает об отсутствии NAT или строгом rp_filter на балансируемых каналах, о чужих fwmark, пересекающихся с fwmark.mask, и об отсутствующих расширениях iptables. keen-pbr status показывает тот же список проблем, что и веб-интерфейс.
      • Endpoint для Prometheus.
        GET /metrics отдаёт задержку проб, выбранный канал, обновления списков, счётчики балансировки и перехвата. Есть дашборд Grafana и примеры алертов. См. REST API.
      • Параметры пакета в keen-pbr test-routing.
        Команда принимает протокол, порты, адреса и DSCP и выполняется в демоне, так же как проверка маршрута в веб-интерфейсе.
      • Трафик самого роутера по умолчанию не трогается.
        Правила маршрутизации действуют на устройства в сети. Чтобы включить и роутер, задайте iproute.process_router_traffic: true. См. iproute.
      • Правило для локальных сетей в конфиге по умолчанию.
        Оно не пускает локальные сети в туннели.
      • Кнопка «Что нового?».
        Она открывает эту страницу из веб-интерфейса.
      • Списки, которые не скачались при запуске, докачиваются в фоне.
      • При удалении пакета убираются оставшиеся правила firewall и файлы dnsmasq.

      Исправления

      • В группы urltest и icmptest теперь можно добавить только участников типа interface и table: другие типы не работали, а теперь не проходят проверку конфига. Участник blackhole никогда не выбирался, теперь keen-pbr пропускает его и пишет предупреждение в журнал. Для блокировки он не нужен: если ни один канал не работает, трафик блокируется сам.
      • Исправлена остановка автообновления списков после первого изменения, влияющего на маршрутизацию. Теперь списки обновляются по расписанию.
      • Исправлено получение адреса по DHCP новыми устройствами, если правило маршрутизации ловит весь UDP-трафик.
      • Исправлен обход правил маршрутизации трафиком самого роутера при заданных inbound_interfaces.
      • Если один список указан в нескольких DNS-правилах, dnsmasq теперь получает серверы всех правил и переключается между ними. Раньше использовался сервер только из первого правила.
      • Keenetic/NetCraze Исправлена сборка маршрутизации по наполовину обновлённой таблице маршрутов, когда при продлении аренды DHCP на WAN маршруты меняются один за другим.
      • Исправлено обнуление файла кэша списка после пропадания питания.
      • Исправлена ошибка, которую keen-pbr status показывал у каждого правила urltest и icmptest.
      • Веб-интерфейс теперь сохраняет conntrack_on_switch, strict_enforcement_action и таймаут пробы urltest при сохранении outbound.
      • Исправлен DNS-сервер с detour через туннель: запросы уходили в туннель с адресом провайдера, и ответа не было. Теперь они идут с адресом туннеля (для серверов с IPv4-адресом).
      • Keenetic/NetCraze Исправлены статические DNS-записи Keenetic и DNS-серверы для отдельных доменов (например, для страницы входа провайдера), когда DNS-сервер типа keenetic выбран DNS-сервером по умолчанию: раньше такие имена уходили на обычные вышестоящие серверы.

      Ломающие изменения (Breaking changes)

      Debian Перед обновлением. keen-pbr 3.3.x зависел от dnsmasq, поэтому apt пометил его как установленный автоматически, и apt autoremove может его удалить. Если dnsmasq вам нужен, сначала выполните:

      bash
      sudo apt-mark manual dnsmasq

      OpenWrtKeenetic/NetCraze Перед обновлением. keen-pbr 3.3.x ставил dnsmasq-full как зависимость, и при обновлении opkg может его удалить. Если dnsmasq вам нужен, сначала выполните по SSH:

      bash
      opkg flag user dnsmasq-full

      Keenetic/NetCraze Если пакет уже удалён и вы включали opkg dns-override, устройства в сети останутся без DNS: роутер по-прежнему отдаёт их запросы dnsmasq, а его уже нет. Веб-интерфейс keen-pbr предложит два варианта:

      • Оставить dnsmasq.
        Установите его снова командой opkg install dnsmasq-full.
      • Обойтись без dnsmasq.
        Выключите Управлять конфигурацией dnsmasq. Затем в веб-консоли роутера (http://my.keenetic.net/a) выполните no opkg dns-override и system configuration save и перезагрузите роутер.

      После обновления управление dnsmasq остаётся включённым, как в 3.3.x. Если dnsmasq вам не нужен, выключите Управлять конфигурацией dnsmasq в веб-интерфейсе (Общее > Настройки > Управление локальным DNS-сервером) и выполните шаги отката: Keenetic, OpenWrt, Debian. Без него не работают DNS-правила и основные DNS-серверы.

      Что проверить после обновления:

      • Модули ядра. Keenetic/NetCraze
        Домены теперь определяются перехватом. Если компоненты Модули ядра подсистемы Netfilter и Пакет расширений Xtables-addons для Netfilter ещё не установлены, установите их. Затем откройте страницу состояния в веб-интерфейсе и запустите проверку DNS.
      • Только iptables. Keenetic/NetCraze
        Сборка для Keenetic всегда работает через iptables. Конфиг с daemon.firewall_backend: "nftables" или strategy: "balance" там не пройдёт проверку.
      • Debian 11 (bullseye) больше не поддерживается.
      • ttl_ms списка стал минимальным сроком.
        Раньше он задавал, сколько хранятся адреса доменов списка. Теперь это минимум: если TTL в ответе DNS длиннее, адрес хранится дольше, но не дольше intercept.max_ttl_ms. Если ttl_ms не задан, минимум берётся из intercept.min_ttl_ms (по умолчанию 5 минут).
      • Изменились значения по умолчанию.
        • daemon.clear_dynamic_sets_on_apply теперь false: адреса доменов сохраняются при применении конфига.
        • iproute.process_router_traffic равно false: правила маршрутизации действуют на устройства в сети, а не на трафик самого роутера.
        • --log-target для всех команд равен both. Пакетные файлы сервиса передают --log-target syslog.
      • Поля, которые больше не работают.
        dns.system_resolver, dns.dns_test_server (используйте intercept.dns.marker) и daemon.resolver_ready_timeout_seconds; если они заданы, журнал предупредит. Старые поля outbounds, candidates и weight в outbound_groups заменены на members. Старые конфиги продолжают работать: keen-pbr один раз перепишет их в новый формат (комментарии и порядок ключей при этом не сохранятся).
      • Новое поле version.
        В нём версия keen-pbr, для которой записан конфиг. keen-pbr ставит его, когда вы сохраняете конфиг в веб-интерфейсе. Если правите файл вручную, оставьте его.
      • Домен для проверки DNS.
        Для ручной проверки запускайте nslookup check.keen-pbr.fyi вместо nslookup check.keen.pbr. См. Решение проблем.

      Если с keen-pbr работают ваши скрипты или другие программы:

      • Команда keen-pbr resolver-config-hash ничего не делает и всегда завершается успешно.
      • keen-pbr generate-resolver-config принимает dnsmasq вместо dnsmasq-ipset и dnsmasq-nftset.
      • keen-pbr status завершается с кодом 1, если какая-то проверка не прошла или среди проблем есть ошибка.
      • GET /api/dns/test?show=all (и show=full) работает только при включённой аутентификации API.
      • Новые endpoint’ы: GET /metrics, GET /api/health/issues, GET /api/config/defaults. GET /api/status/events дополнительно присылает проблемы, состояние маршрутизации, состояние аутентификации и изменения конфига.

      3.3.1

      25 августа 2026

      Что нового

      • Куда писать журнал.
        Параметр --log-target stderr|syslog|both. Сервис по умолчанию пишет в syslog, команды в терминале — в stderr.

      Исправления

      • Переключение открытых соединений.
        Когда выбранный канал в группе urltest или icmptest перестаёт работать, keen-pbr теперь сбрасывает записи открытых соединений в conntrack, и устройство открывает их заново через новый канал, по IPv4 и по IPv6. Раньше соединения оставались на нерабочем канале. Если старый канал при переключении ещё работает, действует настройка conntrack_on_switch.
      • Исправлено отображение состояния участников групп urltest и icmptest (основной, резервный, работает с перебоями, недоступен).
      • keen-pbr ждёт готовности dnsmasq столько, сколько задано в daemon.resolver_ready_timeout_seconds, а не всегда пять секунд.

      3.3.0

      21 августа 2026

      Что нового

      • Большие списки IP-адресов.
        Размер ipset можно увеличить настройками ipset_hashsize и ipset_maxelem: Общее > Настройки > Расширенные настройки маршрутизации.
      • По сигналу SIGUSR1 keen-pbr больше не загружает списки адресов заново. Старое поведение возвращает daemon.reuse_static_sets_on_runtime_refresh: false.
      • Откат конфига.
        Если конфиг не применился, можно вернуть предыдущий.
      • Веб-интерфейс сам подключается снова, если связь с роутером пропала.
      • RAW отдельно для IPv4 и IPv6. Keenetic/NetCraze
        Значения KEEN_PBR_RAW_PREROUTING: auto, enable, disable, ipv4-only и ipv6-only. См. RAW или mangle.

      Исправления

      • Нагрузка на процессор в простое.
        Исправлена: keen-pbr постоянно опрашивал состояние и занимал около 20% процессора (замер на роутере с mipsel). Теперь состояние обновляется по событиям.
      • Устранена одна из причин ошибки Fatal error: control socket timeout waiting for socket ack, из-за которой на слабых роутерах большой конфиг не применялся и не запускался dnsmasq.

      Ломающие изменения (Breaking changes)

      • Значение enable для RAW. Keenetic/NetCraze
        KEEN_PBR_RAW_PREROUTING=enable теперь требует поддержки RAW и для IPv4, и для IPv6. Если RAW нужна только для одного из них, укажите ipv4-only или ipv6-only.

      3.2.1

      15 августа 2026. Версия 3.2.0 не выходила.

      Что нового

      • Пароль на веб-интерфейс и API.
        Вход по паролю, Basic Auth для скриптов и список сайтов, которым браузер разрешит обращаться к API (CORS). Всё это на новой странице Безопасность. См. REST API.
      • Outbound icmptest.
        Проверяет каналы ping-ом (ICMP), а не загрузкой URL. См. icmptest.
      • Роутеру можно дать имя, оно показывается в веб-интерфейсе.
      • Проверка маршрута в веб-интерфейсе переделана. keen-pbr test-routing выводит обычный текст вместо JSON.
      • Неприменённые изменения конфига можно отменить в веб-интерфейсе и через API.
      • В веб-интерфейсе появились ссылки на документацию.
      • Порядок правил маршрутизации можно менять перетаскиванием.
      • RAW или mangle. Keenetic/NetCraze
        В файле /opt/etc/keen-pbr/defaults можно выбрать таблицу, в которой помечается IPv4-трафик устройств. RAW не сбрасывается, когда Keenetic пересобирает firewall, и соединения не рвутся, но работает только для устройств с Политикой по умолчанию. mangle подходит для любых политик из Приоритетов подключений, но правила на время пересборки пропадают. См. RAW или mangle.
      • Пакеты для Debian 11 (Bullseye), 12 (Bookworm) и 13 (Trixie).
      • Полный пакет стал меньше.
      • Репозиторий пакетов переехал с GitHub Pages на отдельный платный хостинг, чтобы реже быть недоступным.

      Исправления

      • Запуск после перезагрузки роутера. Keenetic/NetCraze
        Исправлен: keen-pbr стартовал раньше, чем RCI, и мог не запуститься. Теперь сервис ждёт RCI. Подробности
      • Keenetic/NetCraze Исправлены правила с условием DSCP: модуль xt_dscp теперь загружается сам.
      • Исправлена утечка ресурсов в потоке обновлений веб-интерфейса.

      3.1.1

      26 июля 2026

      Что нового

      • В отчёт диагностики, который скачивается из веб-интерфейса, добавлена последняя системная команда, завершившаяся с ошибкой.

      Исправления

      • iptables Исправлено применение правил iptables, которое в некоторых случаях не срабатывало.

      3.1.0

      25 июля 2026

      Что нового

      • Безопасное применение конфига.
        keen-pbr сначала проверяет новый конфиг и применяет его, ждёт подтверждения от dnsmasq и только потом сохраняет на диск. Если что-то пошло не так, файл на диске остаётся прежним.
      • Применение без перерывов.
        nftables меняется одной транзакцией, а iptables и ipset заменяются без предварительной очистки, поэтому трафик не уходит мимо правил, пока конфиг применяется. keen-pbr удаляет только свои маршруты и правила и не трогает чужие.
      • Строгий режим.
        Если ни один канал не работает, трафик блокируется маршрутом unreachable или blackhole.
      • DNS-запросы самого роутера тоже идут через detour.
      • Условие dscp в правилах маршрутизации.
        Маршрут по метке DSCP (значения 1–63), которую ставит программа на устройстве. См. пример с DSCP.
      • Настройка conntrack_on_switch.
        Задаёт для urltest, что делать с открытыми соединениями при смене канала: preserve или delete.
      • Строгая проверка списков.
        Списки по URL скачиваются только по HTTP и HTTPS, в том числе после перенаправлений. Локальный список должен быть обычным файлом не больше заданного размера. Неправильные домены отбрасываются. Если один и тот же список скачивается несколько раз одновременно, загрузка идёт одна.
      • Веб-интерфейс обновляется сам.
        Изменения состояния сервиса, outbounds и интерфейсов видны сразу, обновлять страницу не нужно. Диагностика и проверка DNS пока так не умеют.
      • При запуске, остановке, перезапуске и применении конфига видно, на каком этапе сервис.
      • Подробная диагностика.
        Видно, совпадает ли конфиг в памяти с конфигом на диске, получил ли dnsmasq актуальный конфиг и каких файлов кэша не хватает.
      • keen-pbr status берёт данные у запущенного сервиса.
      • Метки в таблице RAW. Keenetic/NetCraze
        IPv4-трафик устройств помечается в таблице RAW. Keenetic её не пересобирает, поэтому в играх и звонках меньше обрывов. Если RAW недоступна, keen-pbr предупредит и будет использовать mangle.
      • Keenetic/NetCraze Рядом с системными именами интерфейсов веб-интерфейс показывает их названия из Keenetic.
      • Пакет теперь зависит от conntrack.
      • В API команды apply, start, stop и restart отвечают кодом 202 и номером операции. Если такая команда уже выполняется, следующая получит 409.

        Его можно указать явно.

        Таблицы маршрутизации, fwmark и приоритеты ip rule назначаются по порядку правил.
      • DNS-правила отдельно от маршрутизации.
        Можно задать DNS-сервер для доменов, не меняя их маршрут.
      • Временное отключение правил.
