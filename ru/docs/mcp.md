# MCP-сервер

MCP-сервер позволяет управлять keen-pbr из Claude Desktop, Claude Code и других ИИ-клиентов с поддержкой Model Context Protocol. Ассистент видит состояние маршрутизации, находит причины сбоев, меняет списки и правила — обычными фразами, без ручного редактирования конфигурации.

## Что понадобится

- Node.js 20 или новее на компьютере, где запущен клиент.
- keen-pbr с включённым REST API (`api.enabled: true`).
- API-токен keen-pbr.

### Создание токена

В веб-интерфейсе keen-pbr откройте **Безопасность** > **API-токены**, нажмите **Создать токен** и отметьте права:

| Право | Что открывает |
|---|---|
| `read` | диагностика: состояние службы, маршрутов, outbounds и интерфейсов, проверка маршрута и DNS |
| `read:prometheus` | метрики |
| `write:rules` | добавление и удаление доменов, создание и правка списков и правил |
| `write` | сохранение изменений и обновление списков |

Для полного доступа отметьте все четыре права. Если нужно только смотреть и диагностировать, достаточно `read` и `read:prometheus`.

Скопируйте токен и сохраните в надёжном месте. Токен работает как пароль — не публикуйте его и не пересылайте в чатах.

## Установка

Скачайте репозиторий keen-pbr и соберите MCP-сервер:

```bash {filename="bash"}
git clone https://github.com/maksimkurb/keen-pbr.git
cd keen-pbr/mcp
npm install
npm run build
```

После сборки появится файл `mcp/dist/index.js`. Его полный путь понадобится в настройках клиента.

## Настройка

Сервер читает параметры из переменных окружения:

| Переменная | Обязательна | Значение |
|---|---|---|
| `KEEN_PBR_URL` | да | Адрес API роутера, например `http://192.168.1.1:12121`. Это тот же адрес, по которому открывается веб-интерфейс keen-pbr. |
| `KEEN_PBR_TOKEN` | да | API-токен из раздела **Безопасность** > **API-токены**. |
| `KEEN_PBR_ALLOW_WRITE` | нет | `1` разрешает менять настройки. Без неё ассистент может только смотреть и диагностировать. |
| `KEEN_PBR_TIMEOUT_MS` | нет | Таймаут запроса в миллисекундах, от 1000 до 120000. По умолчанию 15000. |

### Claude Desktop

Откройте `claude_desktop_config.json` (**Settings** → **Developer** → **Edit Config**) и добавьте сервер:

```json {filename="claude_desktop_config.json"}
{
  "mcpServers": {
    "keen-pbr": {
      "command": "node",
      "args": ["/полный/путь/keen-pbr/mcp/dist/index.js"],
      "env": {
        "KEEN_PBR_URL": "http://192.168.1.1:12121",
        "KEEN_PBR_TOKEN": "ваш-api-токен",
        "KEEN_PBR_ALLOW_WRITE": "1"
      }
    }
  }
}
```

Перезапустите Claude Desktop. В списке инструментов появится сервер `keen-pbr`.

### Claude Code

```bash {filename="bash"}
claude mcp add keen-pbr \
  --env KEEN_PBR_URL=http://192.168.1.1:12121 \
  --env KEEN_PBR_TOKEN=ваш-api-токен \
  --env KEEN_PBR_ALLOW_WRITE=1 \
  -- node /полный/путь/keen-pbr/mcp/dist/index.js
```

Если изменения не нужны, уберите строку с `KEEN_PBR_ALLOW_WRITE`.

## Примеры запросов

- «Почему трафик не идёт через VPN?»
- «Куда уходит youtube.com?»
- «Добавь example.com в список my_domains»
- «Создай правило: список my_domains через outbound vpn»
- «Проверь DNS-серверы»
- «Сохрани изменения»

Ассистент сам подберёт нужный инструмент и покажет список изменений. Когда всё верно, скажите «сохрани» — правки вступят в силу после сохранения.

## Инструменты

### Диагностика

| Инструмент | Что показывает |
|---|---|
| `diagnose` | Общая картина: что сломано, какой outbound, интерфейс или список затронут, и что проверить дальше. |
| `get_health` | Состояние службы, версия, режим работы, состояние перехвата DNS и dnsmasq. |
| `get_runtime_outbounds` | Какие outbounds работают, какие деградировали или недоступны. |
| `get_runtime_interfaces` | Список интерфейсов: включён ли, есть ли несущая, какие адреса. |
| `get_command_failure` | Последние неудачные служебные команды, если они записаны. |
| `routing_test` | Куда на самом деле пойдёт домен или IP: ожидаемый и фактический outbound, совпавший список и правило. |
| `dns_test` | События перехвата DNS, TLS и HTTP за короткое окно времени. |
| `dns_check_servers` | Проверка DNS-серверов: отвечают ли и не подменяются ли ответы. |
| `get_metrics` | Краткая сводка метрик Prometheus: ошибки, недоступные проверки, счётчики. |

### Конфигурация

| Инструмент | Что показывает |
|---|---|
| `get_config` | Всю конфигурацию или один раздел: outbounds, списки, DNS, правила. |
| `list_rules` | Правила маршрутизации с номерами, списки, DNS-правила и названия outbounds. |

### Списки

| Инструмент | Что делает |
|---|---|
| `add_domain_to_list` | Добавляет домены в список, при необходимости создаёт список. |
| `remove_domain_from_list` | Удаляет домены из списка. |
| `create_list` | Создаёт список из доменов, IP-адресов, файла или ссылки. |

### Правила

| Инструмент | Что делает |
|---|---|
| `create_rule` | Добавляет правило, например «список my_domains через outbound vpn». |
| `update_rule` | Меняет правило по номеру: outbound, списки, порты, адреса, DSCP или режим default gateway. Ненужное условие можно убрать. |
| `delete_rule` | Удаляет правило по номеру. |

### Применение изменений

| Инструмент | Что делает |
|---|---|
| `save_config` | Сохраняет и применяет изменения. |
| `discard_config` | Отменяет несохранённые изменения. |
| `rollback_config` | Возвращает предыдущую конфигурацию после неудачного применения. |
| `refresh_lists` | Заново скачивает списки по ссылкам. |

## Если что-то не работает

**Клиент не видит сервер.** Проверьте, что в настройках указан полный путь к `mcp/dist/index.js` и что после изменения настроек клиент перезапущен.

**Не удаётся подключиться к роутеру.** Откройте веб-интерфейс keen-pbr по тому же адресу, который указан в `KEEN_PBR_URL`. Если он не открывается, проверьте, что API включён и порт доступен с компьютера.

**Ошибка 401 или 403.** Токен скопирован не полностью или у него не хватает прав. Создайте новый токен с нужными правами.

**Ассистент не меняет настройки.** Добавьте `KEEN_PBR_ALLOW_WRITE=1` в переменные окружения сервера и перезапустите клиент.

**Изменения не применились.** Попросите ассистента сохранить конфигурацию — правки вступают в силу после сохранения.
