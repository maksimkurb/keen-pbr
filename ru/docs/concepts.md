# Принцип работы

Для обычной настройки эту страницу читать необязательно. Она объясняет, как keen-pbr решает, куда отправить трафик.

## Идея в трёх словах: списки, правила, outbounds

Проще всего сравнить keen-pbr с почтовым отделением, которое сортирует письма.

- **Список** — адресная книга. В одной книге записаны сайты, которые вы хотите открывать через VPN, в другой — адреса, которые нужно заблокировать.
- **Правило маршрутизации** — инструкция сортировщика: «письма из этой книги отправь вот этим маршрутом». Инструкции читаются сверху вниз, срабатывает первая подходящая.
- **Outbound** — маршрут доставки: VPN-интерфейс, обычное подключение к провайдеру или «выбросить письмо».

Письмо, адреса которого нет ни в одной книге, уходит обычным маршрутом.

Например, у вас две книги, `streaming` (стриминговые сервисы) и `work` (рабочие сайты). Инструкции такие:

1. Адреса из `local_networks` (ваша домашняя сеть) никуда не отправлять, оставить в сети.
2. Адреса из `work` отправить через рабочий VPN.
3. Адреса из `streaming` отправить через второй VPN.

Всё остальное идёт напрямую через провайдера.

## Списки

Список — набор доменов, IP-адресов и подсетей (CIDR-диапазонов, например `192.168.0.0/16`). Его можно составить из нескольких источников:

- **URL** — список скачивается из интернета и обновляется по расписанию;
- **Файл на устройстве** — список читается из файла на роутере;
- **Домены / IP** — вы вписываете адреса прямо в конфигурацию.

Для доменов вам не нужно знать IP-адреса. keen-pbr сам узнаёт адреса сайтов из списка, когда устройства в сети их открывают, и хранит их ограниченное время. Поэтому после изменения списков стоит очистить DNS-кэш на устройстве: иначе оно может обратиться к сайту по старому адресу, о котором keen-pbr ещё не знает.

Подробности: [Списки]({{< relref "/docs/configuration/lists" >}}).

## Outbounds

Outbound — канал, через который пойдёт трафик. Доступны шесть типов:

| Тип | Что делает |
|---|---|
| `interface` | Отправляет трафик через выбранный сетевой интерфейс, например VPN. При необходимости можно указать шлюзы IPv4 и IPv6 |
| `table` | Отправляет трафик по одной из таблиц маршрутизации роутера. Таблица 254 — обычный выход в интернет через провайдера |
| `blackhole` | Отбрасывает трафик, то есть блокирует его |
| `ignore` | Оставляет трафик как есть: он идёт обычным путём, а правила ниже для него уже не проверяются |
| `urltest` | Сам выбирает лучший из нескольких каналов: проверяет их HTTP-запросом и берёт канал с самой низкой задержкой или распределяет соединения между ними. Нестабильный канал временно исключается |
| `icmptest` | То же, что `urltest`, но каналы проверяются ping-ом ({{< term "ICMP" >}}) |

`ignore` нужен для исключений. Например, правило «домашняя сеть → `ignore`» ставят выше общего правила для VPN, чтобы локальный трафик не попал в туннель.

Подробности: [Outbounds]({{< relref "/docs/configuration/outbounds" >}}).

## Правила маршрутизации

Правило связывает условия с outbound. Условия можно сочетать:

- **Списки** — адрес входит в один из указанных списков;
- **Протокол** — `tcp` или `udp`;
- **DSCP** — метка приоритета трафика;
- **Исходный IP** и **IP назначения** — адрес или подсеть ({{< term "CIDR" >}}), можно с отрицанием;
- **Исходный порт** и **Порт назначения** — один порт, список или диапазон.

Если в правиле несколько условий, трафик должен подойти под все. Правила проверяются сверху вниз, срабатывает первое подходящее. Трафик, который не подошёл ни под одно правило, идёт обычным путём.

Подробности: [Правила маршрутизации]({{< relref "/docs/configuration/route-rules" >}}).

## DNS

Для маршрутизации по доменам настраивать DNS-сервер не нужно. Dnsmasq, DNS-прокси Keenetic или любой другой резолвер работает как раньше. keen-pbr узнаёт адреса сайтов из списков по DNS-ответам и по именам сайтов в соединениях, которые проходят через роутер.

Если для некоторых списков нужны другие DNS-серверы, например чтобы получать адреса CDN нужного региона, используйте [отдельные DNS-серверы для списков]({{< relref "/docs/configuration/dns#per-list-dns-servers-dnsmasq" >}}) (через dnsmasq).

Подробности: [DNS]({{< relref "/docs/configuration/dns" >}}).

## fwmark и conntrack {#fwmark-и-conntrack}

Эти два слова встречаются в логах и в поиске, если что-то пошло не так. Настраивать их обычно не нужно.

- **{{< term "fwmark" >}}** — числовая метка на пакете. keen-pbr ставит её трафику из ваших списков, и по метке роутер понимает, в какой outbound отправить пакет. У каждого outbound своя метка из диапазона, который задан в настройке [`fwmark`]({{< relref "/docs/configuration/advanced#fwmark" >}}).
- **{{< term "conntrack" >}}** — таблица открытых соединений на роутере. Благодаря ей все пакеты одного соединения идут одним путём. Если соединение нужно перевести на другой канал, keen-pbr сбрасывает его запись в этой таблице, и устройство открывает соединение заново.
