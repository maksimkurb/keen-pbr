# Конфигурация

keen-pbr хранит настройки в едином JSON-файле конфигурации.

Расположение файла конфигурации:

- Keenetic / NetCraze: `/opt/etc/keen-pbr/config.json`
- OpenWrt: `/etc/keen-pbr/config.json`
- Debian: `/etc/keen-pbr/config.json`

Если установлен полный пакет, настраивайте keen-pbr в веб-интерфейсе: он сам записывает конфиг, редактировать файл вручную не нужно. Если у вас пакет `keen-pbr-headless` (без веб-интерфейса), правьте файл конфигурации. Настройка состоит из четырёх частей:

- [Outbounds]({{< relref "/docs/configuration/outbounds" >}}) — каналы, через которые может пойти трафик: VPN, провайдер или блокировка
- [Списки]({{< relref "/docs/configuration/lists" >}}) — сайты и диапазоны IP, которые нужно маршрутизировать
- [Правила маршрутизации]({{< relref "/docs/configuration/route-rules" >}}) — какой список через какой outbound
- [DNS]({{< relref "/docs/configuration/dns" >}}) — DNS-серверы и DNS-перехват

В веб-интерфейсе им соответствуют пункты меню **Маршрутизация** > **Outbounds**, **Маршрутизация** > **Списки**, **Маршрутизация** > **Правила маршрутизации** и **Общее** > **Настройки**.

## Практический пример

В этом примере `google.com` идёт через VPN (`tun0`), а весь остальной трафик — как обычно, через основное соединение роутера:

```json
{
  "outbounds": [
    {
      "type": "interface",
      "tag": "vpn",
      "interface": "tun0"
    }
  ],
  "lists": {
    "my_sites": {
      "domains": ["google.com"]
    }
  },
  "route": {
    "rules": [
      {
        "list": ["my_sites"],
        "outbound": "vpn"
      }
    ]
  }
}
```

## Расширенная конфигурация

Для большинства пользователей эти настройки необязательны:

- [Расширенные]({{< relref "/docs/configuration/advanced" >}}) — API, пути сервиса, автоматическое обновление списков и низкоуровневые параметры маршрутизации
- [Полный пример конфигурации]({{< relref "/docs/configuration/full-reference-config" >}}) — пример с комментариями для всех поддерживаемых опций

{{< callout type="info" >}}
Имена списков, теги outbound и теги DNS-серверов должны соответствовать шаблону `^[a-z][a-z0-9_]*$` и не превышать 24 символа.
{{< /callout >}}
