      Outbounds

      Outbounds

      • Open in ChatGPT

      Outbound — канал, через который пойдёт трафик: VPN-интерфейс, обычное соединение провайдера или блокировка. Какой трафик в какой outbound отправить, вы решаете в правилах маршрутизации.

      В веб-интерфейсе: откройте Маршрутизация > Outbounds, нажмите Добавить outbound, введите Название (в конфиге оно называется tag) и выберите тип. Затем нажмите Применить в панели черновика.

      Название (tag): строчные латинские буквы, цифры и _, начинается с буквы, не длиннее 24 символов (^[a-z][a-z0-9_]*$).

      Большинству пользователей достаточно:

      • одного outbound типа Интерфейс (interface) для VPN-соединения
      • одного outbound типа Таблица маршрутизации (table) с table: 254 (основная таблица маршрутизации системы) для обычного соединения, как правило wan
      • при необходимости — одного outbound типа Автовыбор (urltest) или Автовыбор (ICMP) (icmptest), чтобы keen-pbr сам выбирал рабочий из нескольких каналов

      Если не знаете, с чего начать, возьмите Интерфейс и вернитесь к остальным типам позже.

      Общий пример

      config.json
      {
  "outbounds": [
    {
      "type": "interface",
      "tag": "vpn",
      "interface": "tun0",
      "gateway": "10.8.0.1",
      "gateway6": "2001:db8::1"
    },
    {
      "type": "table",
      "tag": "wan",
      "table": 254
    }
  ]
}

      Типы

      interface

      Нужен, когда трафик надо отправить через конкретный сетевой интерфейс: VPN-туннель (tun0, wg0) или отдельное интернет-соединение.

      Поле Тип Обязательно Описание
      tag string да Уникальный идентификатор
      type string да "interface"
      interface string да Имя исходящего сетевого интерфейса (напр. tun0)
      gateway string нет IPv4-адрес шлюза или "auto". В веб-интерфейсе: Шлюз по умолчанию IPv4
      gateway6 string нет IPv6-адрес шлюза или "auto". В веб-интерфейсе: Шлюз по умолчанию IPv6
      strict_enforcement boolean нет Блокировать ли трафик этого outbound, пока его интерфейс или шлюз недоступен. Если не задано, действует общая настройка Блокировать трафик при недоступности outbound (kill-switch) в Общее > Настройки > Общие
      strict_enforcement_action string нет Как блокировать: "unreachable" (соединение сразу завершается ошибкой) или "blackhole" (пакеты молча отбрасываются)

      Для туннелей вроде tun0 или wg0 шлюз обычно не нужен: без gateway и gateway6 трафик IPv4 и IPv6 отправляется прямо в интерфейс. Шлюз нужен, когда интерфейс подключён к роутеру провайдера и трафик надо передать на его адрес, например для второго WAN.

      Шлюз можно не искать самому: укажите "auto" (в веб-интерфейсе введите auto), и keen-pbr возьмёт шлюз из маршрута по умолчанию этого интерфейса в основной таблице маршрутизации (если таких маршрутов несколько — из того, у которого меньше метрика). Если у интерфейса нет такого маршрута или у лучших маршрутов разные шлюзы, outbound считается недоступным для этой версии IP.

      Если задать шлюз только для одной версии IP, трафик другой версии для этого outbound блокируется, а не уходит мимо VPN.

      Kill-switch в форме outbound определяет, что происходит с трафиком, пока интерфейс или шлюз недоступен. Варианты: Поведение по умолчанию (берётся общая настройка), Не блокировать (трафик идёт в обход, через основной маршрут), Блокировать с ошибкой (strict_enforcement_action: "unreachable"), Блокировать молча ("blackhole").

      config.json
      {
  "outbounds": [
    {
      "type": "interface",
      "tag": "vpn",
      "interface": "tun0",
      "gateway": "10.8.0.1",
      "gateway6": "2001:db8::1"
    }
  ]
}

      table

      Нужен, когда трафик надо отправить по уже существующей таблице маршрутизации (набору маршрутов системы): 254 — основная таблица, то есть обычное интернет-соединение, или таблица, которую создал другой сервис.

      Посмотреть, какие таблицы есть и как они называются:

      bash
      ip rule show
cat /etc/iproute2/rt_tables
      Поле Тип Обязательно Описание
      tag string да Уникальный идентификатор
      type string да "table"
      table integer да Номер существующей таблицы маршрутизации. В веб-интерфейсе: ID таблицы
      config.json
      {
  "outbounds": [
    {
      "type": "table",
      "tag": "custom_table",
      "table": 200
    }
  ]
}

      blackhole

      Нужен, чтобы заблокировать доступ к сайтам или адресам: подходящий трафик отбрасывается.

      Поле Тип Обязательно Описание
      tag string да Уникальный идентификатор
      type string да "blackhole"
      config.json
      {
  "outbounds": [
    {
      "type": "blackhole",
      "tag": "block"
    }
  ]
}

      ignore

      Нужен для исключений: трафик идёт по обычной маршрутизации роутера, как будто keen-pbr его не трогает.

      Правила проверяются сверху вниз, и срабатывает первое подходящее, поэтому правило с ignore ставят выше более общего правила. Например, весь список streaming идёт через VPN, кроме адресов из списка streaming_direct (direct — outbound типа ignore из примера ниже):

      config.json
      "rules": [
  { "list": ["streaming_direct"], "outbound": "direct" },
  { "list": ["streaming"], "outbound": "vpn" }
]
      Поле Тип Обязательно Описание
      tag string да Уникальный идентификатор
      type string да "ignore"
      config.json
      {
  "outbounds": [
    {
      "type": "ignore",
      "tag": "direct"
    }
  ]
}

      urltest

      Нужен, когда у вас несколько каналов (например, два VPN и обычный интернет) и keen-pbr должен сам выбирать рабочий. keen-pbr периодически открывает url через каждый канал и измеряет время ответа. В веб-интерфейсе тип называется Автовыбор (urltest).

      Если ни один канал не работает, трафик этого outbound блокируется, а не уходит через обычный интернет мимо VPN.

      Поле Тип Обязательно Описание
      tag string да Уникальный идентификатор
      type string да "urltest"
      url string да URL для проверки доступности и задержки
      interval_ms integer нет (по умолчанию: 180000) Интервал между проверками в миллисекундах
      probe_timeout_ms integer нет (по умолчанию: 5000) Таймаут одной проверки в миллисекундах
      tolerance_ms integer нет (по умолчанию: 100) Не переключаться на другой канал, если он быстрее текущего меньше чем на столько миллисекунд
      strategy string нет (по умолчанию: "priority") Как выбирать канал. В веб-интерфейсе: Стратегия выбора.
      • "priority" (Самый быстрый) — весь трафик идёт через один канал: с самой низкой задержкой в первой рабочей ступени.
      • OpenWrtDebian "balance" (Многопутевая передача) — новые соединения распределяются между рабочими каналами по весу.
      conntrack_on_switch string нет (по умолчанию: "preserve") Что делать с открытыми соединениями при переключении на другой канал. В веб-интерфейсе: Соединения при переключении. "preserve" (Сохранять) — оставить на старом канале, "delete" (Сбрасывать) — удалить их записи из conntrack, чтобы они переподключились. См. Резервный канал
      outbound_groups array да Упорядоченный список групп каналов, в веб-интерфейсе — ступеней (см. ниже)
      retry object нет Повторные попытки проверки (см. ниже)
      circuit_breaker object нет Временное исключение нестабильного канала (см. ниже)
      config.json
      {
  "outbounds": [
    {
      "type": "urltest",
      "tag": "auto_select",
      "url": "https://www.gstatic.com/generate_204",
      "interval_ms": 180000,
      "probe_timeout_ms": 5000,
      "tolerance_ms": 100,
      "outbound_groups": [
        { "members": [{ "outbound": "vpn1" }, { "outbound": "vpn2" }] },
        { "members": [{ "outbound": "wan" }] }
      ],
      "retry": {
        "attempts": 3,
        "interval_ms": 1000
      },
      "circuit_breaker": {
        "failure_threshold": 5,
        "success_threshold": 2,
        "timeout_ms": 30000,
        "half_open_max_requests": 1
      }
    }
  ]
}

      Группы outbound (ступени)

      Группа — это набор каналов, из которых выбирается рабочий. Групп может быть несколько, они идут по порядку: первая — основная, следующие — резервные. keen-pbr использует первую группу, в которой есть хотя бы один рабочий канал. Резервная группа включается, только когда в вышестоящей не работает ни один канал.

      В веб-интерфейсе группы называются ступенями: Основная ступень и Резервная ступень N. Чтобы добавить запасной вариант, нажмите Добавить резервную ступень.

      Поле Тип Обязательно Описание
      members array of object да Каналы этой группы (см. ниже)

      Каждый канал в группе:

      Поле Тип Обязательно Описание
      outbound string да Тег outbound типа interface или table. Ступень для блокировки добавлять не нужно: если ни один канал не работает, трафик блокируется сам
      weight integer 1-100 нет (по умолчанию: 1) OpenWrtDebian Вес канала, в веб-интерфейсе — Вес. Нужен только при strategy: "balance": чем больше вес, тем больше новых соединений получает канал. Каналы с весами 7 и 3 получат 70% и 30% новых соединений, пока оба работают. Если один канал недоступен, его доля делится между остальными. Уже открытые соединения не переносятся
      config.json
      "outbound_groups": [
  { "members": [ { "outbound": "wan1", "weight": 7 }, { "outbound": "wan2", "weight": 3 } ] },
  { "members": [ { "outbound": "backup" } ] }
]

      Многопутевая передача (strategy: "balance")

      OpenWrtDebian
      Эта стратегия распределяет нагрузку между несколькими работающими каналами первой рабочей ступени. Канал выбирается для каждого нового соединения, а не для каждого запроса: всё соединение, включая HTTP/2 и QUIC, идёт через один канал. tolerance_ms и conntrack_on_switch при балансировке не используются. Если канал перестал работать, записи conntrack его соединений удаляются, а новые соединения распределяются между оставшимися каналами.

      nftables Соединения распределяются точно по весам.
      iptables Канал выбирается случайно с нужной вероятностью, поэтому на малом числе соединений доли могут заметно отличаться от весов, а на большом выравниваются. Для iptables нужен модуль ядра xt_statistic; если его нет, keen-pbr сообщит об этом при применении конфигурации. На Keenetic эта стратегия недоступна. С --use-raw-prerouting балансировка недоступна.

      Для балансировки между несколькими WAN нужны NAT на каждом канале, нестрогий rp_filter и диапазон fwmark, который не используют другие программы. Полная настройка для каждого firewall-бэкенда описана на странице Балансировка нагрузки между несколькими WAN.

      Повторные попытки (retry)

      Поле Тип Обязательно Описание
      attempts integer нет (по умолчанию: 1) Сколько всего раз проверять канал, включая первую попытку, прежде чем считать проверку неудачной
      interval_ms integer нет (по умолчанию: 1000) Пауза между попытками в миллисекундах

      Исключение нестабильного канала (circuit_breaker)

      Если канал несколько раз подряд не прошёл проверку, keen-pbr временно перестаёт его использовать. Так трафик не прыгает туда-обратно, когда канал то работает, то нет. Настройки по умолчанию подходят большинству, менять их не нужно.

      Поле Тип Обязательно Описание
      failure_threshold integer нет (по умолчанию: 5) Сколько неудачных проверок подряд нужно, чтобы исключить канал
      timeout_ms integer нет (по умолчанию: 30000) Через сколько миллисекунд снова попробовать исключённый канал
      success_threshold integer нет (по умолчанию: 2) Сколько успешных проверок подряд нужно, чтобы вернуть канал
      half_open_max_requests integer нет (по умолчанию: 1) Сколько проверок одновременно разрешено, пока исключённый канал проверяется повторно

      Исключённый канал отображается как Недоступен на странице Маршрутизация > Outbounds веб-интерфейса и как unavailable в GET /api/runtime/outbounds.

      icmptest

      Нужен вместо urltest, когда проверка по HTTP не подходит. В веб-интерфейсе тип называется Автовыбор (ICMP). Канал проверяется ping-ом (ICMP Echo) конкретного адреса. Для каждого канала в группе задайте target (в веб-интерфейсе — Цель ping): IP-адрес, который будет пинговаться через этот канал.

      config.json
      {
  "type": "icmptest",
  "tag": "auto_ping",
  "interval_ms": 60000,
  "count": 3,
  "max_failed": 0,
  "packet_interval_ms": 200,
  "probe_timeout_ms": 1000,
  "max_rtt_ms": 500,
  "tolerance_ms": 10,
  "outbound_groups": [
    {
      "members": [
        { "outbound": "vpn", "target": "1.1.1.1" },
        { "outbound": "wan", "target": "9.9.9.9", "weight": 3 }
      ]
    }
  ]
}
      Поле Тип Обязательно Описание
      interval_ms integer нет (по умолчанию: 60000) Интервал между проверками, от 1 секунды до 24 часов
      count integer нет (по умолчанию: 3) Сколько ping-ов отправить в каждый канал за одну проверку, от 1 до 10
      max_failed integer нет (по умолчанию: 0) Сколько ping-ов из count может потеряться, чтобы канал всё ещё считался рабочим
      packet_interval_ms integer нет (по умолчанию: 200) Пауза между ping-ами, от 100 до 1000 мс
      probe_timeout_ms integer нет (по умолчанию: 1000) Сколько ждать ответа на один ping, от 100 до 5000 мс
      max_rtt_ms integer нет (по умолчанию: 500) Ответ медленнее этого считается потерянным. Не больше probe_timeout_ms
      outbound_groups[].members[].target string да IPv4- или IPv6-адрес для ping через этот канал (Цель ping)

      tolerance_ms, strategy, conntrack_on_switch, группы (ступени) и веса работают так же, как у urltest.

      Ping-и отправляются по очереди, поэтому проверка всех каналов занимает время. interval_ms должен быть больше этого времени хотя бы на 25%, иначе keen-pbr не примет конфигурацию и напишет минимально допустимое значение. Всего в группах может быть не больше 16 каналов.
